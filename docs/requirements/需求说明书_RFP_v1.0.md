## 1. 项目背景与目标

### 1.1 背景
本地磁盘上常有同一份文件被多次拷贝（改名副本、备份目录、从旧硬盘迁移残留），散落在两个文件夹中时人工核对成本极高，且容易漏判。现有工具多为需安装的商用软件，或功能过载的清理软件，存在捆绑、上传、注册表写入等顾虑。

### 1.2 目标
提供一个**不安装、不联网、不改动系统**的单文件/单目录便携程序，对用户指定的两个文件夹做**内容级重复检测**，输出可核查的重复文件报告，并提供带防护的**一键移动/删除**处置能力。

### 1.3 一句话定义
> 选两个文件夹 → 算出内容相同的文件组 → 看清清单 → 确认后把多余的那份挪走或删掉，全程有日志可追溯。

## 2. 范围

### 2.1 本期范围内（In Scope）
- 两个文件夹的递归扫描与内容哈希计算
- 重复组识别与分类展示（两侧都有 / 仅左侧内部重复 / 仅右侧内部重复）
- 结果浏览、筛选、导出（CSV / HTML 报告）
- 勾选后的批量"移入隔离目录"与"删除"，含二次确认与操作日志
- **一侧独有文件的归并**：把只在一侧出现的文件剪切到另一侧，使该侧剩余文件全部变为重复（FR-10）
- Windows 免安装打包与基础帮助说明

### 2.2 本期不含（Out of Scope）
- 三个及以上文件夹的同时比对（v2 候选）
- 相似文件（非完全相同）识别，如图片感知哈希、文档近似比对
- 内容合并、差异对比（diff）、同步/镜像功能
- 网络共享目录、云盘直连、跨机器比对
- 文件预览（图片/文档缩略图）
- 自动定时扫描、后台常驻、开机自启
- 数据库持久化缓存哈希（v1 不做持久缓存，见 11.3）

## 3. 用户与使用场景

**目标用户**：本机使用者本人（非管理员权限环境，单人单机操作）。

| 编号 | 场景 | 典型诉求 |
|---|---|---|
| S1 | 整理两块硬盘的归档目录 | 找出两个目录里内容相同的文件，保留一份 |

## 4. 功能需求

功能编号规则：FR-xx；验收标准以"可观察、可判定"为准。

### 4.1 FR-01 目录选择

| 项 | 要求 |
|---|---|
| 输入方式 | 左右两个目录各支持：①「浏览…」系统文件夹对话框；② 手动粘贴/输入路径；③ 拖拽文件夹到对应区域 |
| 路径校验 | 路径不存在、无读取权限、左右为同一路径或其父子包含关系时，给出明确提示并禁止开始 |
| 记忆 | 退出时保存上次两个路径及全部选项到程序同目录 `config.json`，下次启动自动回填 |
| 展示 | 显示所选目录完整路径，路径过长时中间省略并可悬停查看全文 |

**验收**：拖入不存在路径时按钮置灰并提示原因；重启程序后上次路径已回填。

### 4.2 FR-02 扫描选项

| 选项 | 默认值 | 说明 |
|---|---|---|
| 递归子目录 | 开 | 关闭时仅扫描两个根目录第一层文件 |
| 跳过隐藏/系统文件 | 开 | 依据 Windows 文件属性判断 |
| 跳过零字节文件 | 开 | 0 字节文件视为无意义重复，不计入结果 |
| 最小文件大小 | 0 字节 | 可设阈值（如 1 MB），小于阈值不参与比对 |
| 排除规则 | 空 | 可填扩展名列表（`.tmp;.log`）与目录名黑名单（`node_modules;.git`），分号分隔，不区分大小写 |
| 跳过符号链接/软链接/junction | 开（不可关闭） | 防止循环引用与越界访问 |

**验收**：排除 `.git` 后该目录文件不出现在结果；关闭递归后结果中无二级目录文件。

### 4.3 FR-03 重复判定标准（核心）

**判定标准（唯一生效标准）：两文件内容哈希值一致即为重复。**

| 项 | 要求 |
|---|---|
| 哈希算法 | 默认 **SHA-256**；可切换 MD5（仅用于本机提速，界面需标注"安全性较低，仅用于重复检测"） |
| 读取方式 | 流式分块读取，块大小 1 MB，禁止整文件载入内存 |
| 大文件 | 单文件 ≥ 4 GB 必须能正常计算，不因大小失败 |
| 判定依据 | **文件名、扩展名、修改时间、所在目录均不参与判定**（改名副本必须被识别为重复） |
| 零误判 | 哈希一致的两个文件必须判定为重复；哈希不一致的两个文件必须判定为不重复 |
| 空文件 | 按 FR-02 默认跳过；若用户关闭"跳过零字节"，则所有空文件归为一组 |

> **设计说明（需用户留意）**：严格"纯哈希"意味着每个文件都要完整读一遍。工程上存在一个**语义等价**的加速手段——"大小不同则内容必然不同"，先按大小分桶再对同大小文件算哈希，结果与纯哈希**完全一致**，但能显著减少读取量。该优化在 v1 中列为**可选项，默认关闭**，界面注明"不改变判定结果"。是否启用由用户在开发前决定（见 12-①）。

**验收**：构造同名但内容不同的文件对 → 不得判为重复；构造内容相同但文件名/大小写不同的文件对 → 必须判为重复。

### 4.4 FR-04 扫描过程

| 项 | 要求 |
|---|---|
| 进度展示 | 显示当前阶段（枚举 / 计算哈希 / 汇总）、已处理文件数、已读字节、当前文件名、预计剩余时间 |
| 界面响应 | 扫描在后台线程/进程执行，界面不冻结，可随时**取消** |
| 取消语义 | 取消后不产生任何结果与任何文件操作，回到初始态 |
| 错误容忍 | 单个文件读取失败（占用、权限拒绝、路径过长）不中断整体扫描，计入"跳过清单"并注明原因 |
| 双目录独立性 | 左右目录分别扫描，一侧失败不阻塞另一侧 |

**验收**：扫描中界面可拖动、可点击取消；放入一个被 Excel 占用的文件后扫描完成并出现"跳过：文件被占用"条目。

### 4.5 FR-05 结果展示

结果区以分组为单位呈现，支持在"重复组 / 仅左侧 / 仅右侧 / 跳过项"四个视图间切换。

**重复组条目字段**：组号、哈希（可折叠显示）、副本数量、单个文件大小、合计占用、可释放空间（= 大小 ×(副本数-1)）、每个副本的：完整路径、所在侧（左/右）、大小、修改时间、勾选状态。

**组分类标签**：
- `跨目录重复`：左右两侧都出现该哈希（核心价值场景）
- `仅左侧内部重复` / `仅右侧内部重复`：同侧内多个副本
- 单个哈希只在某一侧出现一次 → 不构成重复，归入"唯一文件"

**排序与筛选**：可按可释放空间降序、组内副本数降序、路径字母序排序；可按"仅显示跨目录重复"过滤。

**顶部汇总条**：扫描文件数、重复组数、重复文件总数、可释放空间总量（人类可读单位）。

**验收**：任一组内所有副本哈希值相同；可释放空间汇总与各组之和一致（允许 ±0）。

### 4.6 FR-06 报告导出

| 格式 | 要求 |
|---|---|
| CSV | UTF-8 with BOM（Excel 直接打开不乱码），列：组号、哈希、副本序号、所在侧、完整路径、大小(字节)、修改时间、是否建议保留、组内可释放空间 |
| HTML | 单文件、无外链、内嵌样式；含扫描参数、汇总统计、分组表格；可直接双击打开或打印 |
| 保存位置 | 默认保存到左侧目录同级或用户指定；文件名含时间戳如 `dup-report_20261122_1530.csv` |

**验收**：CSV 用 Excel 打开无乱码、列对齐；HTML 断网可正常显示。

### 4.7 FR-07 处置动作（移动 / 删除）

#### 4.7.1 保留策略
每组必须**至少保留一份**，程序层面强制：不允许用户把某组全部副本都标记为处置对象。保留对象可由三种方式确定：

1. 手工勾选（默认）
2. 「保留左侧」/「保留右侧」/「保留修改时间最早」/「保留路径最短」——一键为全部组应用策略

#### 4.7.2 动作一：移入隔离目录
- 目标：用户在动作面板指定一个隔离目录（**不得位于左右两个根目录之内**，程序需校验并拒绝）
- 移动时在隔离目录内**保留相对路径结构**，如 `隔离目录\左\子目录A\文件.txt`
- 同名冲突自动追加 `(1)(2)` 序号，不覆盖
- 移动成功后可一键"撤销本次移动"（依据日志把文件挪回原位，仅在原位置未被占用时生效）

#### 4.7.3 动作二：删除
- 默认走**回收站**（Windows 原生删除，可手工还原）；"永久删除"必须单独勾选且额外确认
- 只读文件、隐藏文件删除前自动清除只读属性（记录在日志）

#### 4.7.4 安全防护（强制，不可关闭）
1. **预演清单**：执行前弹出确认对话框，列明"将处置 N 个文件、共 X GB，每组保留哪一份"，需用户点击「确认执行」
2. **边界锁定**：仅允许处置本次扫描过、且路径位于两个根目录之内的文件；任何越界路径程序拒绝执行
3. **占用检测**：执行前对每个目标文件做可写性检测，被占用/无权限的跳过并标注，不强行处理
4. **操作日志**：每次执行在程序同目录 `logs\` 下生成 `操作日志_时间戳.csv`，字段：时间、动作类型、原路径、目标路径/删除方式、文件大小、哈希、结果（成功/跳过/失败）、失败原因；日志**只追加不覆盖**
5. **结果回执**：执行结束展示"成功 N / 跳过 M / 失败 K"，并可点击打开日志所在文件夹
6. **不做递归删除目录**：v1 只处置文件，不删除因清空而变空的目录（仅提示）

**验收**：把隔离目录设为右目录的子目录时被拒绝；对一组内全部副本取消保留时，执行被拒绝；执行后在日志中可逐条追溯且路径正确。

### 4.8 FR-08 界面与易用性

- 单窗口三段式布局：顶部目录选择 → 中部选项与操作 → 底部结果区（可折叠）
- 全中文界面，术语与本文档一致
- 关键危险按钮（删除/永久删除）用醒目配色 + 二次确认，与安全色（导出/移动）区分
- 支持高 DPI 缩放（125%/150% 下不模糊、不遮挡）
- 提供「帮助」入口，解释判定标准与"保留一份"规则
- 空状态、扫描中、无结果、有结果四种界面状态均有明确文案

### 4.9 FR-09 关于/版本信息
显示程序版本、哈希算法、构建日期，便于后续定位问题。

### 4.10 FR-10 归并（一侧独有文件剪切到另一侧）

**目的**：把"只在一侧存在"的文件搬过去，使被搬空的那一侧不再有独有内容——从此该侧的每一个文件都能在另一侧找到内容相同的副本，这一侧就可以整体清理。与 FR-07 的重复处置互为前后两步。

#### 4.10.1 方向与目标
- 方向二选一：`A 侧独有 → 剪切到 B` 或 `B 侧独有 → 剪切到 A`，界面用分段按钮切换，默认「A 侧独有 → 剪切到 B」
- 目标根目录 = 另一侧的根目录，**不可另行指定**
- 目标路径 = 目标根目录 + 源文件的相对路径（相对源根目录），即**保留目录结构**，如 `D:\归档\照片\2025\x.jpg` → `E:\迁移\旧硬盘\照片\2025\x.jpg`

#### 4.10.2 冲突策略（强制：绝不覆盖）
目标位置已存在同名文件时，按用户选择的策略处理，默认「追加 (1)(2) 序号重命名」：

| 策略 | 行为 |
|---|---|
| 追加序号（默认） | 生成 `名称 (1).pdf` 等新名，不覆盖 |
| 跳过并记录 | 该文件不移动，记入跳过清单，执行继续 |

> 无论哪种策略，**任何情况下不得覆盖目标侧已有文件**；若目标同名文件内容恰好相同，也按策略处理并记录（默认重命名会多出一份，因此建议先看预览）。

#### 4.10.3 前置校验
1. 归并只搬"独有文件"，**跳过项（占用/无权限/零字节/符号链接）不参与**，并在预览中单列
2. 目标根目录必须可写；不可写时禁止执行
3. 目标不能是源目录的父子目录（防止把文件搬进自身子树造成无限嵌套）
4. 若同一源相对路径在目标侧是一个**目录**而非文件，判定为冲突，按策略处理并记录

#### 4.10.4 预演与执行
- 必须先生成**归并清单**：逐项显示「源路径 → 目标路径」，附冲突标记（正常 / 需重命名 / 将跳过）
- 清单顶部给出：文件数、总字节、冲突数、跳过数
- 用户确认后执行，显示进度条与当前文件名，可取消（已完成的移动不回滚，但会完整记录在日志中）
- 完成后展示回执：成功 N / 重命名 M / 跳过 K / 失败 F，并提供「撤销本次归并」

#### 4.10.5 完成后的状态提示（本功能的关键输出）
归并成功后自动提示并给出实测数字：

> 「A 侧原有 21,038 个文件，已剪切 5 个独有文件到 B 侧。当前 A 侧 21,033 个文件**全部可在 B 侧找到内容相同的副本**。可继续用「保留 B 侧」策略清理 A 侧重复副本，或直接删除整个 A 侧目录。」

- 提示中的数字必须来自重新扫描结果，不得沿用归并前的缓存值
- 提供「重新扫一遍确认」按钮，重扫后若仍存在该侧独有文件，明确列出未归并成功的原因

#### 4.10.6 日志与撤销
- 与 FR-07 共用同一套操作日志，动作类型记为 `归并移动`，额外记录源/目标路径与是否发生了重命名
- 撤销本次归并：按日志把文件移回原位；若原位已被占用或已存在同名文件，该条列入失败清单，其余继续

**验收**：归并后重扫，该侧「独有文件」数量为 0；目标侧无任何文件被覆盖；日志条目数与实际移动数一致；撤销后可完全还原。

### 4.11 FR-11 顶端任务运行监控（v1.2 追加）

| 卡片 | 必含内容 | 说明 |
|---|---|---|
| 整体比对进度 | 百分比、进度条、阶段标签（空闲/运行中/已完成/已取消）、已完成与总文件数、吞吐 MB/s、剩余时间、当前最大文件自身百分比 | 百分比以字节为口径；枚举阶段显示已遍历目录数与已发现文件数 |
| 本工具 CPU | 进程 CPU 占用%（可超 100%，多线程合计）、系统总占用%、近 60 秒迷你曲线、峰值 | 用于判断「是否吃满 CPU」「是否被别的程序拖慢」 |
| 本工具内存 | 进程工作集 MB、峰值 MB、系统已用%条、物理内存总量 | 超过 300 MB 需在日志中告警（对应 NFR-03） |
| 磁盘 IO | 本工具读 MB/s（主值）、写 MB/s、迷你曲线、累计读/写字节 | 反映是否受磁盘吞吐限制 |

- 监控面板常驻顶端，可折叠为一行摘要（进度 / CPU / 内存 / IO）。
- 采样周期 1 s；每次开始比对时重置峰值。

### 4.12 FR-12 本地运行日志（v1.2 追加）

- 底部常驻日志面板，流式追加：启动信息、比对开始（含两侧路径与选项）、枚举统计、每跨 10% 的哈希进度、疑似卡住、手动跳过、完成统计、跳过项（最多 20 条 + 汇总）、处置结果、归并结果、撤销结果、错误。
- 同时写盘 `logs\运行日志_YYYY-MM-DD.log`：`时间戳 \t 级别 \t 内容`，逐行 flush，按天追加。
- 面板支持收起、「打开目录」、「清空视图」（仅清界面，不动磁盘文件）。
- 与既有 `操作日志_YYYY-MM-DD.csv` 分工：**运行日志 = 过程事件流**，**操作日志 = 可审计的逐文件处置记录**（撤销依据），两者独立、互不覆盖。

### 4.13 界面视觉（v1.2 修订）

- 卡片式仪表盘：浅灰底 `#F2F4F8`、白色圆角卡片（12 px）、细阴影、主色蓝 `#2B6CF6`、状态胶囊标签、迷你面积图。
- 比对区维持「单一滚动轨道 + 左右两列 + 1px 中缝」，行高 56 px，同内容左右严格对齐，一侧滚动另一侧跟随；换皮不改变结构与交互。

## 5. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 免安装 | 便携目录形式（`FileDupCompare\` 内含 exe 与依赖），**不写注册表、不装服务、不需管理员权限、不联网**；删除目录即彻底卸载 |
| NFR-02 | 启动性能 | 冷启动至可用界面 ≤ 3 秒（SSD、常规配置） |
| NFR-03 | 规模 | 单侧 ≤ 10 万文件 / 总量 ≤ 2 TB 可完成扫描；不因文件数过多内存溢出（内存峰值 ≤ 300 MB） |
| NFR-04 | 吞吐 | 顺序读盘条件下哈希吞吐不低于磁盘顺序读速率的 60%（多线程并行哈希） |
| NFR-05 | 稳定性 | 连续扫描 3 次不崩溃、不泄漏句柄；处理异常路径不得崩溃退出 |
| NFR-06 | 兼容性 | Windows 10 1809+ / Windows 11，x64；路径含中文、空格、emoji、`#`、`%` 均正常 |
| NFR-07 | 长路径 | 支持总长度 > 260 字符的路径（内部使用 `\\?\` 前缀处理） |
| NFR-08 | 编码 | 所有导出的文本类文件默认 UTF-8 with BOM |
| NFR-09 | 可维护性 | 代码分层：扫描引擎 / 判定逻辑 / 界面 / 处置与日志，互不耦合；关键逻辑有单元测试 |
| NFR-10 | 隐私 | 全程离线，无任何网络请求、无遥测 |
| NFR-11 | 进度可观测（v1.2 追加） | 进度以「已读字节 / 总字节」为口径，采样间隔 ≤ 0.3 s；单个文件连续 6 s 无字节增长须判定为「疑似卡住」并给出可操作的跳过入口 |
| NFR-12 | 自身开销可观测（v1.2 追加） | 顶端监控须每秒采样并展示本进程 CPU 占用、工作集内存、磁盘读写速率与累计量，采样本身开销 ≤ 1% CPU |
| NFR-13 | 日志留存（v1.2 追加） | 运行日志按天落盘、逐行 flush，异常退出前的最后一条事件不应丢失；日志不记录文件内容，只记录路径、大小、哈希与结果 |

## 6. 技术约束与建议方案

| 项 | 建议 | 理由 / 取舍 |
|---|---|---|
| 语言 | Python 3.11+ | 开发快、hashlib 可直接分块计算、路径与异常处理成熟 |
| 界面 | PySide6（Qt） | 表格性能与高 DPI 表现优于 Tkinter，10 万行结果不卡；代价是打包体积较大（约 60–90 MB） |
| 哈希 | `hashlib.sha256` + 4 线程池（I/O 密集，线程优于进程） | 避免进程间传数据开销 |
| 打包 | PyInstaller `--onedir`（便携目录） | `--onefile` 每次启动需解压，冷启动常 5–8 秒，不满足 NFR-02；onedir 虽多文件，但符合"免安装"（拷走整个目录即可运行） |
| 删除 | `SHFileOperation` / `IFileOperation` 送回收站 | 用户可手工还原，风险最低 |
| 配置/日志 | 程序同目录 `config.json`、`logs\` | 便携化，不留系统残留 |

> 若坚持"单文件 exe"，需接受启动时间放宽到 ≤ 8 秒，并注明杀软首次扫描可能更慢。此项见 12-②。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 误删重要文件 | 高 | 默认走回收站；强制每组保留一份；预演清单 + 边界锁定 + 日志；移动优先于删除 |
| 纯哈希在大数据量下耗时长 | 中 | 多线程；清晰进度与预计剩余时间；"大小预筛"作为可选项（语义等价，默认关） |
| onedir 目录被误拆散 | 中 | 说明文档明确"整个目录一起拷走"；exe 检测缺失依赖时给友好提示 |
| 杀软误报 PyInstaller 产物 | 中 | 说明文档注明；可提供源码与打包脚本供自行构建 |
| 长路径/特殊字符处理遗漏 | 中 | T-05/T-06 强制用例；统一走 `\\?\` 封装函数 |

## 12. 待你确认的开放项（确认后即冻结开发范围）

1. **是否启用"大小预筛"优化**：语义等价、结果不变，仅影响速度。建议启用（大数据量下提速明显）。默认关。
2. **打包形态**：`onedir` 便携目录（启动 ≤3s，推荐）vs 单文件 `onefile`（启动 5–8s，更"干净"）。
3. **删除默认方式**：回收站（推荐）vs 直接永久删除。是否需要保留"永久删除"入口。
4. **是否需要「撤销本次移动」**：推荐保留（成本约 0.5 人日），若不需要可省。
5. **可释放空间口径**：按"每组 大小×(副本数-1)"统计（推荐，等价于"每组只留一份"的最优结果），是否认可。
6. **界面框架**：PySide6（体积大但体验好，推荐）vs Tkinter（体积小、体验一般）。
7. **归并冲突策略默认值**：追加序号重命名（推荐，绝不多覆盖）vs 直接跳过并记录。
8. **归并完成后是否推荐清理**：完成提示里直接给出「按保留另一侧策略清理重复副本」入口（推荐），或只显示提示文字。
